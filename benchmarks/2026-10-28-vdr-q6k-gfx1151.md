# 2026-10-28 — dense Q6_K VDR=2 on gfx1151: neutral at B=1/B=4/depth, +1.2 % at batched B=8, width-pure (r170, issue #228 follow-up)

**`WORKLOG.md` 261028.012** + [`GREEDY-PURITY.md`](../GREEDY-PURITY.md) §68 + block 07 in
[`patches/README.md`](../patches/README.md) + `ENVIRONMENT.md` §14.  The measurement behind keeping upstream
#30517's `VDR_Q6_K_Q8_1_MMVQ 1 -> 2` as the delivery default on every arch, and behind the build-time
`-DGGML_HIP_Q6K_DENSE_VDR1` escape.

## Why this was measured

A gfx1151 consumer (issue #228, comment 6483065646) gated their release adoption on **output identity** across
base bumps and found r150's greedy text moved against their r120 reference, bisected to upstream `2744e48d1`
(#30517).  Block 07's own per-arch gate (`RDNA4`/`RDNA3_0` -> VDR=2, VDR=1 elsewhere) had been re-scoped by
the `6050b467c` re-base absorbing upstream's unconditional `2`, so gfx1151 (RDNA3_5) had moved 1 -> 2 without
a delivery decision or a measurement.  This record is that measurement.

## Setup

* Box: Strix Halo, Ryzen AI MAX+ 395 / Radeon 8060S, **gfx1151**, 128 GiB unified, 16 cores.
* ROCm `10.1.0-gfx1151`; build via `~/bin/build-llama-rocm` (`GGML_HIP_NO_VMM=ON`, `GGML_HIP_RCCL=1`,
  `GGML_CUDA_FA_QUANTS` at the canonical set), `-t 8`.
* Payload: `/llm/models/Qwen3.8/Flash-Next/Q5K` (3 shards, 86 GiB) — tensor census **339 Q5_K / 199 Q8_0 /
  94 IQ3_S / 44 IQ4_NL / 2 IQ4_XS / 13 Q6_K**, the Q6_K ones being `output.weight` (the lm_head,
  2560x248320) and the 12 full-attention `attn_output.weight` (6144x2560).  That is the same census class the
  reporter filed, so the arm exercises the tensors #30517 changed.
* Draft for the width-purity arm: `/llm/models/Qwen3.8/Flash-Next/IQ4_NL/mtp-Qwen3.8-Flash-Next-shared-Q8_0.gguf`
  (the shared Q8_0 MTP head), used with `--spec-type draft-mtp`.
* Two binaries from the same tree, differing only in the macro: the default (`VDR_Q6_K_Q8_1_MMVQ 2`) and a
  rebuild with `VDR_Q6_K_Q8_1_MMVQ 1` — i.e. exactly what `-DGGML_HIP_Q6K_DENSE_VDR1` selects.  Each arm's
  `bin/` was copied out and run by absolute path (`RUNPATH` is `$ORIGIN`), so the two never shared a library.

## Result

Interleaved, 2 reps per cell, `llama-bench -r 3` / `llama-batched-bench` (`-npp 512 -ntg 128 -npl 1,4,8
-ctk q8_0 -ctv q8_0`):

| metric | VDR=2 (default) | VDR=1 (restored gate) |
|---|---|---|
| `tg128` | 33.86 / 33.86 | 33.83 / 33.81 |
| batched B=1 `S_TG` | 33.50 / 33.49 | 33.48 / 33.47 |
| batched B=4 `S_TG` | 81.76 / 81.72 | 81.75 / 81.55 |
| batched B=8 `S_TG` | **104.14 / 103.98** | 102.94 / 102.60 |
| `tg128 @ d16384` | 31.86 | 31.86 |

So: **neutral at B=1, B=4 and at depth; +1.2 % at batched B=8** for the shipped default.  Batched prefill
(`S_PP`, closed-loop) is flat (846 -> 842 t/s at every B; the Q6_K prefill path is `VDR_Q6_K_Q8_1_MMQ = 8`
and is not touched by this macro).

**Greedy text moves between the builds**, as an association-order change must: one prompt, 128 tokens,
`--seed 42 --temp 0`, generated-text hash `d47f08557f75` (VDR=2) vs `bf8ddd5271d1` (VDR=1).

**Width purity holds at VDR=2** — this is the invariant that matters, and the one a cross-release text gate
cannot see.  `prompts/reasoning.txt`, `-c 8192 -n 200 --seed 42 --temp 0`, target + shared Q8_0 MTP head:

| arm | chars | sha |
|---|---|---|
| `plain` | 1302 | `115141867744` |
| `draft-mtp --spec-draft-n-max 3` | 1302 | `115141867744` |
| `draft-mtp --spec-draft-n-max 7` | 1302 | `115141867744` |

Decode with the draft: 50.0 t/s (`n_max 3`) / 41.6 t/s (`n_max 7`) vs 33.6 t/s plain — the MTP win on this
payload is intact under VDR=2.

## Flags-off is a no-op

The delivery change is comments + one preprocessor condition, so with the flag off the built tree must
behave exactly as before.  Verified on the rebuilt default tree: 128-token greedy `d47f08557f75` (identical
to the pre-change VDR=2 binary) and `draft-mtp n_max 7` `115141867744` (identical to `plain`).

The flag-on arm was compiled on gfx1151 (`mmvq.cu` command line + `-DGGML_HIP_Q6K_DENSE_VDR1`: object
15 189 864 B vs the default's 15 218 536 B) and reproduces the VDR=1 binary's text `bf8ddd5271d1`.

  --seed 42 --temp 0 --no-display-prompt --single-turn
