## 1. State of the world

The FA prefill **staging arena** (`fattn_stage[]` in `ggml_backend_cuda_context`) holds an F16 copy of the
K/V rows the FA op reads.  It is O(prefix) because `launch_fattn` converts the whole prefix **before one
FA kernel launch** whose blocks walk the whole KV extent.  That single fact is the root of #138 (growth
stranding on WDDM), #237 (eager over-commit) and the #237 follow-up (a late 1 GiB step landing in shared
memory), and it is why a whole family of memory workarounds exists around it.

**Settled:** the staging must not be removed — it is worth **+1.5 / +2.7 / +5.1 %** pp at 8k/16k/32k over
the native read (27B UD-Q4_K_XL, 1 GPU, q8_0 KV).  The interim answer (outcome **C**) shipped as
`beta/fa-stage-peak/`: one early allocation, eager by default on Windows, plus a draft-context cap.  That
bounds the *commitment*, not the *size*.

**This task** is the size: tile the conversion, so the arena is a handful of MiB at any depth.

## 4. The two dead ends (do not repeat) and the real blocker

1. **Per-output-tile grid** (prototype v1: `blocks_num = (ntiles_x, 1, nz)`, `parallel_blocks = 1`):
   numerically fine but **2.8x slower**, because the MMA kernel's work decomposition is
   `kbc = blockIdx.x * total / gridDim.x` — it ignores `blockIdx.y/z`, so a per-tile launch leaves only
   `ntiles_x` blocks doing the KV walk and the `z` blocks redo the same work.  **MMA prefill is
   stream-K-only.**  `parallel_blocks > 1` is likewise not implemented for the MMA kernel (the write path
   always normalizes unless the flags say otherwise).
2. **A per-decode projection** (`min(hint, F16 of n_past + n_tokens)`, to size the arena by the request):
   degenerates into a ladder, because `llama_context::decode()` sees one *batch* and the caller loops —
   measured **10 allocations for one 32k prefill**.  A request-sized projection needs `common`/server to
   pass the request length; that is a delivery change, not this task.  (Recorded in
   `beta/fa-stage-peak/README.md`.)

**The real blocker:** the stream-K partials are published in two different contracts.  A block that *starts*
a tile writes a **normalized** value to `dst` (`needs_fixup=false`); a block that continues it writes
**unnormalized** data + meta; the fixup kernel folds them into a **final normalized** value and only visits
tiles that have a **seam**.  So a tile whose KV sits inside one block publishes a correct number and **no
`(max, rowsum)` at all** — which is exactly why the first stream-K chunking attempt produced NaNs, and why
"the combine already exists" (M1's optimistic read) was not enough.

## 5. The design to implement

**Give the kernel a partial mode in which every block publishes `(unnormalized value, max, rowsum)` for its
own rows, and let the fixup overwrite both for seam tiles.**  Then every output row has exactly one
publisher, and the launcher can merge chunks with an online-softmax update.

Concrete edits (small; the prototype patch already contains most of the plumbing):

1. **`kv_partial` flag** — one new trailing `int` on `fattn_kernel_t`, the MMA kernel and `process_tile`
   (tile/vec kernels take it unnamed and ignore it).  `launch_fattn` passes `0` everywhere except the
   chunk loop.  *(prototype has this.)*
2. **Suppress the divide in partial mode** at `fattn-mma-f16.cuh:2411`:
   `if (!needs_fixup && !is_fixup && !kv_partial) { … /= KQ_rowsum_j; }` — so a no-seam tile publishes an
   *unnormalized* value that the launcher can weight.
3. **Publish element-major meta for the no-seam (first-block) case too.**  The three `needs_fixup` sites
   already write `dstk_fixup[...]`; add the same write to the `!needs_fixup` path (or, simpler: make every
   block in partial mode take the `needs_fixup` code path — that is what the prototype does with
   `kb0_start == 0 && !kv_partial`).  Row index: `((jt*ncols1 + j_dst)*ne02 + c_dst)` with the **row base**
   `sequence*ne01.z*ne02 + zt_Q` folded into the `dstk_fixup` pointer by the caller (the prototype's
   `dst_meta_kv`), plus the tail guard
   `(ncols1 == 1 || jt*ncols1 + j_dst < ne01.z) && (ncols2 == 1 || zt_gqa*ncols2 + c_dst < gqa_ratio)`.
   **Note `sequence`/`zt_Q` are not available inside `process_tile`** — the pointer pre-offset is the way in.
4. **`kv_start` for the two absolute-KV optimizations.**  Make the chunk a multiple of
   `max(nbatch_fa, FATTN_KQ_STRIDE)` (i.e. 256 for RDNA4 prefill configs) so the group offset is exact, then:
   `fattn_kq_group_masked(kq_blocks, kb0, nbatch_fa)` → index `(kv_start + kb0*nbatch_fa)/FATTN_KQ_STRIDE`;
   and the `KV_max` bound → `min(kb0_stop, max(0, KV_max[…] - kv_start) / nbatch_fa)`.  Thread one
   `int kv_start` (rows) into the kernel.  Both optimizations are *exact*, so keeping them is
   correctness-neutral — measured as ~0 pp on this box, so this is optional; **do it anyway** for the
   multi-slot/server case the group skip was built for.
5. **Partial mode in the two fixup kernels** (`:1355`, `:1466`): when non-null `kv_partial_meta`, write
   `part_meta[row] = (max_val, rowsum)` and `*dst = dst_val` (unnormalized) instead of dividing.  *(prototype
   has this.)*  Rows in **no-seam** tiles are not visited by the fixup at all — that is why (3) is required.

Launcher side (prototype, reusable as-is): ring = `2 × chunk_rows × (K+V)` F16 bytes served by
`fattn_stage_try_get(stream, ring_bytes)` (so the slab wide-aux home, `--fit` accounting and `SLAB_STATS`
keep working); per chunk `to_fp16_nc(rows [k0,k1))` into slot `c % 2`, launch with `ne11 = nc` and
chunk-dense strides (`nb12 = nc*nb11`), the fixup in partial mode, then
`flash_attn_chunk_merge` (online softmax) and `flash_attn_chunk_finalize`.  Chunk boundaries: every chunk
exactly `C` except the last, which absorbs the remainder, so no chunk is shorter than 2 KV tiles (a
1-tile chunk has no stream-K split at all → no fixup → no partial).

## 6. Numerics, purity, gates

* **A re-baseline is expected and legitimate**: chunk boundaries move the fp16 `VKQ` accumulator grouping
  (measured 6.6302 → 6.6261 at 4 chunks).  `scripts/gate-prefill-logits.sh --kv q8_0` at a **re-recorded
  base**; the limits stay mean KLD ≤ 0.005 / same-top-p ≥ 98 %.
* **The band must not move.**  `native_width = Q->ne[1] <= 8` keeps decode/verify out of the staging path
  entirely; `test-logits-width-probe` at `P >= 4096` (GREEDY-PURITY §51) and `plain == draft-mtp` text.
* `test-backend-ops -o FLASH_ATTN_EXT` (the mask/type matrix) and `-o FLASH_ATTN_QSA` (the sparse path stays
  single-launch — do not chunk `use_sparse`).
* **Never benchmark in parallel**, pin `HIP_VISIBLE_DEVICES` (device 3 is the iGPU), and remember
  `llama-bench` installs a **null log callback** — use `llama-cli -v` to see `FA_STAGE`/`SLAB_*`
  (`FINDINGS-2026-10-27-m0.md` §F0).

## 7. Risks / open decisions

* Highest-risk file in the delivery: `fattn-mma-f16.cuh` also carries the decode-band gear and its
  width-purity invariant.  Keep every band path bit-identical.
* Numeric cost scales with the number of chunks; pick `C` from the pp/arena trade (2048-8192 rows on the
  27B: 17-67 MiB) and measure 2-3 values.
* Whether to keep the whole-prefix mode as the default and make chunking opt-in (`GGML_CUDA_FA_STAGE_CHUNK`)
  or the other way round is a **maintainer decision** once the numbers are in; the campaign's decision
  criteria are in `README.md` §6.

## 8. Step 0 (do this first, it is the whole risk)

Prove the row contract **alone**, on the existing single-launch path: set `kv_partial` for a normal
(unchunked) prefill of a shape with ≥ 2 stream-K blocks per tile, run the fixup in partial mode into a
scratch `part`/`part_meta`, then run `flash_attn_chunk_finalize` into the op's output.  Expected: **PPL
identical to the baseline to 4 decimals** (no chunk boundaries were introduced; only the publish/merge
order of an existing split changed).  If that is not identical, the protocol is wrong — fix it before
touching the launcher.
