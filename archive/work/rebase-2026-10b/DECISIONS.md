Companion to [`README.md`](README.md).  Classification is the same as the October campaign's:
**SUBSUMES** (upstream's version replaces ours), **CORDON** (ours is kept deliberately; upstream's code stays
available but unreached), **INTEGRATE** (both, merged), **UNION** (both, additively).

## Delivery-internal decisions this re-base forced

| topic | decision |
|---|---|
| **MMQ J-tile selection** | Upstream factored it into `ggml_cuda_mmq_get_J_best()` at one anchor where the delivery adds `ggml_cuda_mul_mat_q_switch_type_gate()` + `ggml_cuda_mmq_select_J()`.  Ours is a **strict superset** (RDNA3.5/RDNA4 routed-compact bands, `GGML_Q6_COMPACT_J`, the fused-gate register cap, and `GGML_CUDA_MMQ_J_MAX`).  So upstream's helper is now a thin **delegate** to `ggml_cuda_mmq_select_J(…, has_ids=false, has_gate=false, …)` and both of its call sites keep working.  `GGML_CUDA_MMQ_J_MAX` moved *inside* the selector so both call sites honour it (it used to be read only at the dense site). |
| **Routed-compact MoE MMQ** (`mmq_routed_compact`, RDNA3.5/RDNA4) | Kept whole; excluded from `has_gate` (it has its own epilogue path) and from `has_fusion`.  Its `mul_mat_q_process_tile` call was updated to the merged signature (leading `x_gate`, explicit `GGML_GLU_OP_COUNT/0.0f`). |
| **Block 10's moved dispatcher** | The 3-way merge must use the **pre-move** tree as `base` (`05da4346b` = the old chain's block 09), not the rebased block-09 tree: with the latter, upstream's additions look "unchanged" and are silently dropped (first attempt did exactly that — 0 conflicts, feature missing).  `git merge-file ours base theirs` with base = old block 09, ours = block 10's `ggml-cuda-try-fuse.cu`, theirs = the new base's `ggml-cuda.cu` region → **0 conflicts, both sides' arms present**.  Verified by grep for `ggml_cuda_should_fuse_mul_mat_q` in the merged TU. |
| **`ggml_cuda_should_fuse_mul_mat_q` visibility** | Defined in `ggml-cuda.cu` (next to the matcher the graph optimizer uses) and called from the moved TU, so it lost `static` and gained a declaration in `ggml-cuda-try-fuse.cuh` — the same treatment `ggml_cuda_fusion_disabled` and `ggml_cuda_device_malloc` already have.  **Not** a patch-order `#ifdef`. |
| **`mmq_args`** | Carries **both** fused-arm carriers: upstream's `ggml_cuda_mm_fusion_args_device fusion` and the delivery's `x_gate`/`glu_op`/`glu_limit`.  The launcher picks per template parameter (`has_gate ? args.x_gate : args.fusion.gate`). |
| **`mmq.cuh` write-back** | Upstream's `has_fusion ? tile_C::ne/2 : tile_C::ne` / `I/2` write-back **and** the delivery's `split_j` (`warp_i`/`warp_j`) mapping coexist; they cannot co-occur (the gate caps `J ≤ 64` for Q8_0, `split_j` requires `J == 128`). |
| **`qwen4exp` MTP head mixer** | Kept the delivery's `cb(cur, "mtp_hc_head")` with `il = -1` and **no `res->t_embd`** (the wide stream is exported via `t_h_nextn`; see the comment in that function), while adopting the new `build_hc_mix` signature. |
| **K/V cache type equality** | Block 10's general hard-reject (`params.type_k != params.type_v` for *every* arch) kept over upstream's MLA/DeepSeek4-only check.  The markers for this one were committed inside block 10's tree by accident; fixed by amending block 10 (see README "Process lessons"). |
