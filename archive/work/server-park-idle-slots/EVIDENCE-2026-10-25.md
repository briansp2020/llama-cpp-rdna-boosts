# Evidence — idle-slot parking (r136, 2026-10-25)

Gfx1201, ROCm 10.1.0, `~/bin/build-llama-rocm` (canonical r136 tip `43505eac8`).  Server:
`llama-server -m Qwen3.8-27B-UD-Q4_K_XL -md Qwen3.8-27B-DFlash2-Q4_K_M --spec-type draft-dflash
--spec-draft-n-max 5 -np 4 -c 131072 --kv-unified -fa on -ctk q8_0 -ctv q8_0 --seed 42 --temp 0`.
16 varied prompts (each with a common 20-line filler in the shared-prefix arm), sent one at a time in two
rounds, `n_predict 8`, greedy.

## The core comparison

| arm | round 1 vs round 2 | equal to lazy-off, both rounds |
|---|---|---|
| parking (default) | **16/16** | **32/32** |
| `LLAMA_SERVER_LAZY_IDLE_SLOTS=0` | 16/16 | — |
| `LLAMA_SERVER_PARK_IDLE_SLOTS=0` (#210) | 13/16 | 13/32 |

`cache_prompt: false`; only the first two lines are the same request set.

The same 16 prompts with `cache_prompt: true` share the filler prefix, so a cached restore creates cells
shared through `seq_cp` and parking refuses (`seq_park: seq N: its M cells are not one run of its own`).
Both parking and lazy-off then measure 12/16 across rounds and are still **32/32 equal**: the fallback is
the lazy-off output, not a parking defect.  This is why the reporter's "no fallback fired" is specific to
their request set, and their 16/16 is specific to it as well.  A run with no shared prefix and
`cache_prompt: false` is the clean gate above.

`LLAMA_KV_PARK_DEBUG=1` shows the actual moves, e.g. with four prompts and no fallback:

```
seq_park: seq 0 [0, 241) -> [130831, 131072)
seq_unpark: seq 0 [130831, 131072) -> [0, 241)
park_compact: seq 1 [130598, 130831) -> [130839, 131072)
```
